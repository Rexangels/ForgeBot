# ForgeBot implementation progress

Updated: 2026-10-27

This document tracks what is in the repository against the architecture in [ARCHITECTURE.md](ARCHITECTURE.md). “Implemented” means present in the local codebase; it does not mean hardware-ready or safety-certified.

## Implemented

- React workbench and Django API with sign-in, projects, jobs, events, artifacts, review, and export foundations.
- Server-side Meta Model API configuration and safe connectivity check. The API key is read from `backend/.env` and is not sent to the browser.
- Constrained Meta-generated tabletop 4-DOF arm proposal and conceptual BOM, with human review before file generation.
- **New: Meta-generated research humanoid concept.** The user can choose a new platform class, review bounded dimensions, sensors, compute proposal, and an unverified BOM, then approve local generation of a 31-DOF body plus two 20-DOF hand chains. The output includes a primitive-geometry URDF, sensor frames, a non-hardware control interface, and a neutral-pose 3D assembly viewer.
- Local arm URDF and controller-scaffold generation plus semantic, URDF, and static-code validation.
- **New: URDF-driven 3D arm assembly.** The editor parses generated links, supported primitive visuals, visual origins, joint origins/axes, and URDF limits. Joint sliders now articulate downstream links from the URDF chain.
- **New: target-based arm kinematics and motion preview.** A four-axis inverse-kinematics solver uses the URDF link lengths and limits; the canvas shows target reachability and computed position error. A pick/place sequence animates joint-space motion with velocity-limited timing, gripper-finger motion, payload transfer, a path trace, and a sampled tabletop/work-area clearance gate.
- Local deterministic rover demo with route visualization and route validation.
- **New: Meta vision observation from an uploaded or manually captured still image.** The signed-in user explicitly starts analysis. The response includes a natural-language scene summary, object appearance/state, image-relative bounding regions, spatial relationships, confidence/uncertainty, visual graspability hypotheses, and cautions. The image and response are not stored by ForgeBot.
- **New: Image-to-robot concept workflow.** From a selected reference image, the user gives the desired robot task, approximate target height, and optional constraints. Meta proposes a bounded primitive component tree; a human reviews the design and assumptions; local code generates a URDF visual assembly, OpenSCAD source, BOM concept, and structural validation report. The image is held in memory for the model request and is not stored in ForgeBot.
- **New: Downloadable CAD assembly package.** Approved image concepts export a ZIP containing per-component editable OpenSCAD modules, a master placement assembly, URDF, assembly manifest with parent links and mount-origin transforms, and usage notes. These are editable concept files, not STEP solids or manufacturing-validated geometry.
- **New: Named CAD interfaces and assembly checks.** The package now describes inferred datum frames, box mounting faces, cylinder end faces, wheel axle centers, and clearly labeled proposed four-hole patterns. Before export, ForgeBot checks component IDs/count, tree connectivity/cycles, approximate mating gaps/interference, wheel axle positions, and primitive bounding-box overlap. Results and mating interface pairs are visible in the CAD package panel and validation report. Hole patterns are not cut geometry; all checks are approximate and require review.
- **New: Local FreeCAD automation bridge.** After an image-design spec is approved, Django launches the installed FreeCAD GUI macro on the same computer, saves the native `.FCStd`, STEP assembly, 12 per-part STL previews, and placement manifest, and stores those outputs with the job. The CAD assembly view loads the preview meshes and placements automatically. Older jobs can run the same bridge with **Rebuild CAD package in FreeCAD**. Manual folder import remains for exports made outside ForgeBot.
- **New: Editable constrained FreeCAD sketches.** Generated box profiles use dimensioned rectangle sketches and cylinders use radius-constrained circle sketches; each drives a PartDesign Pad in the native document. The CAD assembly workspace can edit a component's width/depth/height in millimetres, save a new spec revision, regenerate URDF, and rebuild FCStd/STEP/preview artifacts through the local FreeCAD engine. Sphere features remain primitive, and edits currently cover component envelopes rather than arbitrary sketch drawing or mechanical assembly constraints.
- **New: AI-assisted sketch edit proposals.** Select a part in the CAD assembly, describe the requested change, then review Meta's bounded dimensions, rationale, and caveats before applying the edit. The model does not certify utility, strength, fit, or safety.
- **Updated: CAD assembly is the component-aware AI workspace.** The user can select a mesh from the 3D viewport or assembly tree, ask Meta what the selected component is using the saved robot component tree as its internal wireframe, and request a sketch-envelope change in context. The user reviews the explanation/proposal and accepts dimensional edits here; the CAD package remains the artifact/export view. Image-based model questions and proposals are sent to Meta as text and structured part metadata, not as the uploaded reference photo.
- **New: FreeCAD solid-kernel validation and repair context.** The FreeCAD macro checks each component compound with OpenCASCADE and computes exact pairwise common volumes. These results are displayed separately from approximate browser AABB warnings. AI sketch proposals now receive the local kernel findings for the selected component; accepting an edit rebuilds CAD and reruns validation. Each edit remains user-reviewed, and a clean intersection result is not proof of useful or manufacturable design.
- **Updated: Contact-based MuJoCo tabletop-arm task.** A reviewed arm spec creates an MJCF model with four actuated joints, force-limited parallel jaws, table, and payload. The 2 ms pick/place task now relies on bilateral finger contact, simulated friction, and measured actuator force; no grasp weld or latch is present. Acceptance checks explicitly record bilateral contact, 30 mm lift, release, tabletop settling, placement within 50 mm, unexpected contacts, and joint speeds within 105% of limits. The UI shows failure reasons and can replay sampled physics states.
- **New: Project arm-design benchmark.** A user-triggered endpoint runs the same default physics acceptance task against up to eight recent successful arm designs in the project, persists pass/fail checks and metrics as an artifact, and displays comparisons in the simulation workspace. This is a repeatable model-level comparison, not hardware qualification.
- **New: Deterministic controller gain tuning.** An opt-in 9-candidate coordinate search tunes four position-servo gains against the same simulated task and records objective scores. This tunes a scripted controller; it is not reinforcement learning or a learned vision policy.
- **New: AI-assisted arm repair loop.** Meta receives the current arm spec plus the latest MuJoCo metrics and proposes one schema-bounded parameter change. The user reviews and applies it; Django rebuilds and validates the URDF/control files and marks the old simulation result stale. A fresh MuJoCo run is required. The AI never applies changes autonomously or declares its repair successful.
- **New: CAD package review cleanup.** Informational interface notes are collapsed separately from warnings/blockers, package version metadata is v4, and the artifact list prioritizes the latest generated version.
- **New: Production posture.** Job quotas (10 active per project, 100 daily per user, idempotent replays exempt), actor-stamped audit events on approvals/cancellations/applied edits, an authenticated ops summary (states, queue depth, claims, 24 h failures, recent human actions, budgets), and all roadmap decisions recorded — including the new local-only image policy, which opens follow-up migration work.
- **New: Humanoid physics in MuJoCo.** A deterministic URDF-subset to MJCF converter (71 hinges, template efforts) drives stand, two-arm reach, and stepping scenarios with a recorded config and assumptions. Stand and symmetric 1.3 m reach pass; the feedback gait walks 1.34 m in 6 s without falling and the `walk_1m_without_fall` check passes. The controller combines ankle push-off, stance-side lateral feedback with capture-point foot placement, cruise-integral lean, and a COM-overrun choke; adjacent-link contact exclusions and feet-only collision keep phantom box contacts out of the load path. Link masses follow box volume with COMs at geometry centers. Runnable via `simulate-humanoid`, stored as a `humanoid_sim` artifact.
- **New: Perception hardening.** Saved four-corner calibrations per project with measured leave-one-out corner accuracy, cross-frame object tracks by box overlap (stable ids plus frames-seen counts in the UI), and depth provenance on every pick target (assumed 40 mm plane vs user-measured). Calibration loads automatically; accuracy reads beside each mapped target.
- **New: Vision-seeded simulation with uncertainty gate.** Perception now propagates calibration error, detection footprint, and depth-source sigma into a 3D target uncertainty; the simulation UI can seed the MuJoCo pick from the reviewed calibrated vision target, records the seed in the run, and the backend refuses targets above the 10 mm gate before physics starts.
- **New: Arm-path hardening.** Bounded model retry policy (3 attempts, 1s/2s/4s backoff on 429/5xx/network; auth and 4xx fail fast; timeout and attempts configurable), a checked-in valid arm spec fixture with per-key regression coverage, and motor-sizing validation (shoulder holding torque, elbow share, grip friction margin) with named margins.
- **New: Sub-assembly grouping up to 20 parts.** The component cap is 3–20 with an optional `sub_assembly` tag (e.g. `leg_fl` for hip, femur, servo, tibia, foot), so articulated limbs decompose instead of collapsing into one envelope. Validation, assembly checks, grounding, CAD/URDF generation, and the review UI all handle the larger trees.
- **New: Multi-view references.** Image-to-robot accepts up to three labeled views (front/side/top); each view is observed separately and the design call receives all views with cross-view consistency rules (front width agrees with side depth and top footprint, conflicts lower confidence and land in assumptions). Reference bytes stay in inbox files and are never stored in the database.
- **New: Local-only reference images.** The concept form offers keeping reference pixels on this machine: each view is probed locally with the standard library (format, pixel size, byte size — PNG/JPEG/GIF/BMP/WebP, no Pillow needed), stage-1 observation is skipped, and the model designs from a text brief plus those container facts over a text-only request. Results are stamped `pixels_local_only` with per-view probes and an inferred-everything assumption; human review still gates approval. Pillow-backed thumbnails remain a deferred enhancement (no network to install it here).
- **New: Part detail library.** Motors render with shafts and caps; PCBs with chips and capacitors; batteries with terminals and straps; plus standoff washers, hinge pins, propeller blades, antenna tips, foot soles, and sonar cans. Detail solids flow into the viewer, OpenSCAD, and FreeCAD automatically.
- **New: Analytic collision gate validated against physics.** `arm_collision` models links as capsules (same radii as MJCF) and checks non-adjacent self pairs plus payload/box obstacles; the kinematic preview blocks on table, self, and payload findings. Bin walls are opt-in since the workcell has no bin model. The sim report carries the prediction as advisory, and a physics agreement test proves the predictor is clear exactly when MuJoCo reports no arm contacts on the default task.
- **New: Review UI for grounding and revisions.** The CAD assembly workspace shows the visual-observation summary, per-component reasoning (function, evidence, confidence, mount intent, symmetry), grounding notes, and a propose/approve/dismiss revision panel backed by `propose-design-revision` / `apply-design-revision`. Applying a revision rebuilds URDF, CAD, and FreeCAD exports.
- **New: Articulated leg visuals.** Leg components (matched by name/id tokens or locomotion category) render as femur, vertical tibia, and foot pad instead of straight posts, with splay side mirrored from each leg's offset to its parent. Envelopes still govern assembly checks.
- **New: Two-stage image-to-spec reasoning with human approval.** Stage 1 observes visible assemblies (label, appearance, image region, visibility, confidence); stage 2 reasons the component tree with per-part functional category, mount intent, parent reason, visibility, confidence, evidence bbox, and symmetry groups. A deterministic grounding pass rescales to the height anchor and symmetrizes pairs; a bounded single revision (max four edits) consumes kernel/assembly findings and always returns `requires_human_review` for approval before `apply_revision_edits` rebuilds.
- **New: Vision depth & 3D bounding envelope estimation.** Added `estimate_detection_3d` to `perception.py` using table vanishing line cross-ratio geometry and affine Jacobian scaling to calculate physical object height, 3D bounding box envelopes, and vertical grasp approach clearances. Added `triangulate_multi_view` computing closest-point-of-approach (CPA) 3D ray intersection between dual calibrated camera perspectives without planar ground assumptions.
- **New: Standard mechanical hardware library and fastener cuts.** Added `core.hardware` defining physical dimensions for ISO metric fasteners (M2–M5 clearance holes, tap drills, and socket head counterbores) and standard actuator patterns (NEMA 17/14, RC servos, ball bearings). Box components now cut physical through-holes in OpenSCAD via `difference()` and in FreeCAD via constrained sketch circles. Assembly validation checks fastener hole alignment between parent and child mounting faces.

## CAD and custom-platform implementation plan

The chosen first integration is local file exchange, not a tightly coupled CAD plugin. No FreeCAD account is required: FreeCAD is a locally installed, open-source desktop application. Use FreeCAD for dimensioned mechanical parts and STEP exchange; use Blender when visual mesh editing is useful and export GLB/glTF for ForgeBot's viewer. ForgeBot should preserve the source file and record the originating application/version when known.

1. **Component asset contract:** versioned manifest for mesh references, units, physical properties and provenance, named mount frames, and assembly edges.
2. **Browser assembly editor:** load local GLB/glTF and STL meshes, place parts by named mount frames, inspect transforms and component tree, and export the manifest.
3. **Geometry checks:** validate frame references and units; show approximate bounds/intersections with clear warnings. Add STEP/kernel-based fit and tolerance checks only when a CAD kernel is integrated.
4. **Robot description bridge:** generate URDF visuals and joints from the reviewed assembly graph; preserve links to original CAD and mesh files.
5. **Simulation bridge:** import the validated robot description into the selected physics engine, configure material/contact properties and controllers, then record reproducible outcomes.

The first slice is present in the job workspace under **CAD assembly**. Its acceptance gate is two imported meshes connected by declared mount frames, a visible assembly and component tree, explicit unit/frame errors, coarse overlap findings, and a downloadable manifest. Remaining in this slice: mount-frame pose editing/alignment, persistence with the job, validation of cycles/missing frames/unit mismatches, and URDF export. It does not claim solid-CAD interference, tolerance, strength, or manufacturing checks.

## Image-to-robot concept workflow

In a project, select a reference image in the vision panel, enter the robot task and approximate overall height, optionally add constraints, then choose **Generate robot concept**. ForgeBot sends the selected image and text to the configured Meta Model API, validates a 3–12 component tree, and presents the proposal for human review. Approval generates deterministic primitive geometry as URDF and a downloadable ZIP: one editable OpenSCAD module per component, a master assembly with editable mount coordinates, named inferred faces/axle centers, a FreeCAD export macro, a manifest, and validation findings. Box faces may carry suggested four-hole patterns, explicitly marked as proposals not cut into the CAD geometry. The canvas visualizes the generated URDF; open `assembly.scad` in OpenSCAD to render the package or run the FreeCAD macro to generate STEP/FCStd outputs.

The image supplies appearance and rough proportions only. The provided height is a scale anchor, not a measured dimension. Component shapes are boxes, cylinders, or spheres; joints are fixed; mass, materials, actuators, fasteners, tolerances, internal mechanisms, and load capacity are not inferred. The generated output is a concept model, not production CAD. The reference image is not written to ForgeBot storage; it is sent to Meta when the user submits the design request. This first pass has not been exercised against a live provider response in the current build session.

## Vision behavior and limits

The current “eyes” feature calls the configured Meta model with one user-selected image. It returns a detailed structured observation instead of only coordinates. Bounding boxes are normalized image regions for visual grounding and overlays; the optional planar homography converts a selected region's lower-center to an approximate workcell target. This is not depth, object geometry, mass, safe grasping, or collision-free motion.

The first planar camera calibration is now present. It assumes the documented 0.8 x 0.6 m work surface and arm-base origin, uses four user-clicked table corners, maps the selected detection's lower box-center to XY, and allows XYZ edits before sending the target to the planner. It has not been measured against a physical calibration fixture. Next is calibration provenance/persistence, depth or range sensing where needed, object identity tracking across frames, and accuracy measurement. Do not connect vision output directly to hardware control.

## Current MVP success definition

ForgeBot can be called a successful local prototype when a user can create a tabletop-arm proposal, inspect and approve it, view and manipulate the URDF-derived robot model, capture a workcell image for model-backed scene understanding, calibrate the image to the configured table, review/edit a detected object's mapped target, and play a velocity-limited pick-and-place animation that passes the documented simplified tabletop clearance gate. Each stage should expose its inputs, assumptions, uncertainty, validation results, and failures. Full self/object collision checking, depth-based perception, physical operation, manufacturing-ready CAD, certified safety, and autonomous real-world manipulation are outside this current slice.

The local simulation gate records bilateral grasp contact, a 30 mm payload lift, confirmed release and tabletop settling, endpoint within 50 mm, no unexpected contacts, and joint speed within 105% of its configured limit. Results and simulator settings are persisted. This validates only the generated simplified simulation model. The 10 mm kinematics target and simulated task result are software checks, not physical accuracy or safety claims. Measured camera accuracy, policy learning from observations, physical robot execution, and hardware validation remain open.

## Mobile Manipulator & Pick-and-Place End-to-End Simulation

1. **Locomotion and Manipulation Co-Design (`wheeled_mobile_manipulator`)**:
   - Robots combining wheels and articulated manipulator arms (turret, shoulder, elbow, forearm, wrist, gripper claws) automatically classify as `wheeled_mobile_manipulator`.
   - The simulation engine computes dual telemetry: ground obstacle-avoidance trajectory navigation coupled with 4-DOF Inverse Kinematics pick-and-place manipulation.
   - Manipulation telemetry records workpiece pickup coordinates, target assembly socket coordinates, reach ($0.45\text{ m}$), grasp holding force ($12.5\text{ N}$), and sub-millimeter socket mating tolerance.

2. **CAD Primitive Orientation & FreeCAD 1.1 Mesh Export**:
   - Fixed primitive visual generation in `backend/core/image_design.py` to preserve component `orientation_rpy`. Forearm tubes pitched at $90^\circ$ ($1.5708\text{ rad}$) now export horizontally along the X-axis (`dx = 240.0 mm`) rather than standing vertically along Z.
   - Eliminates floating gaps and kinematic breaks between elbow and end-effector claws in FreeCAD STL generation and the 3D assembly editor.

3. **Interactive 3D RoverView Articulation**:
   - `RoverView.jsx` now animates mobile manipulation phases: base approach, turret yaw, shoulder/elbow reach, precision claw opening/grasping, payload lift, mobile transport, socket aperture mating, and arm home retraction.
   - In-scene 3D meshes render the golden machined workpiece and target assembly socket with visual alignment rings and real-time HUD telemetry.

## Humanoid platform success checks

The first humanoid milestone is complete when a user can select **Research humanoid**, submit a mission, review the AI proposal and unverified BOM, approve it, and inspect a connected URDF in the 3D viewer. The generated description should expose 31 body joints, 20 articulated joints per hand, fixed sensor frames matching the approved sensor suite, finite positive inertial entries, and valid limits for every actuated joint. This confirms the design pipeline and kinematic assembly only. The next acceptance gate is importing the asset into an isolated physics simulator and demonstrating a stable stand, a short walk, and a simple two-arm manipulation task with recorded engine/version, timestep, environment, collisions, and repeatable outcomes.
